# M8 monitoring and exit implementation plan

> **For agentic workers:** Use superpowers:executing-plans inline, task by task.

**Goal:** Implement SPEC §7–8 only, with tests first and honest runtime readiness.
**Architecture:** Reuse the fixed dev pool, pinned rollout/token pipeline, detectors,
and local frozen-teacher hook. Generate before/teacher/after behavior runs,
score checkpoint rollouts locally for full-vocabulary KL and persist evidence.
The separate exit command generates user-selected paired retention evidence and
compares exactly behavior agreement plus retention. Behavior reports can run
before retention settings exist.
**Tech Stack:** Existing Python, Pydantic, torch, verifiers and prime-rl pins.
**Spec:** docs/SPEC.md §7–8; docs/DETECTORS.md §4–5.

## Global constraints
- M8 only; no GRPO training, reward optimization, SFT, merge or deployment.
- Endpoints generate only. No teacher scoring endpoint or API.
- Shared suffix IDs are recorded IDs; labels never enter RLM prompts.
- No acceptance thresholds or retention dataset invented; required null settings
  fail closed. Scope covers server implementation and local CPU/HTTP checks.
- Preserve incomplete decontamination, passed gate and CUDA checks.
- Work in the existing untracked shared project; no parent-repo branch/commit changes.

## Review focus
- Missing/unknown detector evidence cannot pass exit checks.
- Incomplete, stale, modified, fixture or wrong-checkpoint evidence cannot pass.
- Behavior reports must run without retention settings; exit requires those settings.
- Local scoring preserves teacher/adapter state, alignment, bounded projections.
- Failure/cancellation preserves partial logs and closes all resources.
