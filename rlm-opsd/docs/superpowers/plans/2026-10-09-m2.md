# M2 implementation plan

Implement TASKS.md only. The user authorized this milestone and requested tests
first. Existing SPEC/TASKS are the design; no M3 prompt or later training work.

1. Test deterministic generation for all six families, context formats and seeds;
   independent answer recomputation and mutation detection; corpus/TREC guards.
2. Implement structured record renderers, seeded generators, source provenance,
   separate verifiers, pinned BANKING77 import, and real process-pool generation.
3. Test and implement held-out adapters and decontamination: normalized exact
   queries, configurable word n-gram Jaccard overlap, shared source IDs/content
   hashes. Preserve eval-only routing and report incomplete benchmark coverage.
4. Materialize a mixed candidate pool, context files, manifest, per-cell counts,
   and decontamination report. The user has no local benchmark snapshots. Public
   artifacts actually obtained will be distinguished from missing full corpora;
   incomplete coverage must prevent training-loader release.
5. Run answer verifiers, serial/parallel reproducibility, decontamination and the
   complete M0/M1/M2 suite. Record commands, counts, source licenses and unrun
   full-data checks, then stop at M2.

Grid eligibility follows task semantics: small-context controls only below the
configured direct-read limit; repo QA uses a list of file strings. Other families
support str/list and plain/JSONL/CSV/log/Markdown encodings. Report exclusions,
not padded fake large small-context controls. Default generation covers every
eligible size bucket; family ratios and split seeds are explicit config values.
