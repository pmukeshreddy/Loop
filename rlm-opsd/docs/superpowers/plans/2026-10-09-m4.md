# M4 detector implementation plan

Implement `docs/DETECTORS.md` only, following the user's test-first authorization.
No teacher-gate/evaluation sweep, loss, or training implementation. Source docs,
prompt files, model/dependency pins, and M2 datasets remain unchanged.

1. Write hand-labelled positive/negative trajectories for D1–D19, including
   numeric rates/categories, and failing tests for AST facts, provenance, tag
   requirements, missing evidence and malformed input. Implement config, a
   bounded AST fact extractor, detector evaluation and tag checks.
2. Independently write failing tests and implement root-token category/offset
   mapping and summaries of supplied per-token divergence values. Do not
   re-tokenize rollout IDs or mislabel sampled logprob differences as full KL.
3. Independently write failing tests and implement offline Markdown/CSV report
   aggregation with phases before/teacher/after, grouping, denominators and
   trajectory links. Only supplied real or explicitly labelled fixture records
   contribute numbers; absent runs stay absent.
4. Add a tested metadata-only trajectory extension (type/lengths, no raw context)
   for coverage geometry, and a tested offline CLI. Legacy logs may supply task
   metadata separately; missing/unresolved evidence is unknown, never a pass.
5. Run targeted red/green checks, fixture CLI, full regression suite, source/API
   verification, read-only review, and final artifact audit. Log all in PROGRESS.

Thresholds are required fields in `configs/detectors.yaml`, initially null; tests
use explicit labelled fixture values. No gate/exit thresholds are invented.

The AST analyzer never executes trajectory code. It tracks context-derived
values, search IDs/positions, variable reuse, computed values and subcall results
in source order. Supported literal/bounded operations can resolve slice geometry;
unsupported/dynamic control flow is surfaced as uncertainty. Coverage measures
the union of context ranges supplied to reads/searches/scans/subcalls, with a
separate known lower bound when exact geometry is unavailable. Logged calls
provide actual prompt lengths/counts, not an AST estimate of runtime call counts.

Independent implementation interfaces:

- `analyze_trajectory(trace, config, *, task_metadata=None)` returns a JSON-safe
  dict: `task_id`, `family`, `domain`, `tags`, `size_bucket`, `detectors` (D1–D19),
  `task_tag_match`, `counts` (`subcall_count`, `subcall_mean_prompt_chars`,
  `subcall_max_prompt_chars`, `truncation_events`, `syntax_error_blocks`,
  `code_blocks`), `coverage_lower_bound`, `unknown_reasons`, and `facts`.
  Detector values are bool, float, category string or null. Nulls never satisfy
  required tag rules.
- Offline report rows have `phase`, `trajectory_path`, `analysis`, optional
  `task_success`. Reporter handles each detector's type, known/unknown counts,
  phase/family/size_bucket/domain breakdowns, and links its source logs.
- Token category helpers take text plus supplied character offsets; divergence
  summaries take aligned caller-supplied values and metric kind. No model calls.

Review focus: aliases/reassignments and dead code; observation ambiguity and
tracebacks; failed/oversized subcalls and loops; Unicode/overlapping offsets;
missing phase groups/unknown denominators and trace source attribution.
