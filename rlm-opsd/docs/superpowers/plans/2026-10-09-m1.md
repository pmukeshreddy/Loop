# M1 implementation plan

Scope: SPEC §2 only, authorized by the user's M1 request. Preserve the supplied
root specifications; add canonical links under docs/ and prompts/.

1. Write and run contract tests before implementation: metadata, fenced code and
   finish parsing, persistent REPL, bounded output/tracebacks, final variables,
   last-turn execution, subcall limits/concurrency/routing, resource limits, JSON.
2. Implement `rlm_opsd.harness` using the pinned RLM training worker/backend
   interfaces and an `RLMTrainEnv` subclass. Process responses when added to the
   verifiers trajectory, before its stop checks. Keep root token IDs unchanged.
3. Configure budgets in `configs/harness.yaml`. Use a separate frozen client;
   recursion defaults off. Bound subprocess output in the worker and enforce
   wall/RSS/CPU budgets in the parent; retain Linux kernel limits as a backstop.
4. Run the real subprocess and full verifiers loop with deterministic local
   client responses. No external model, GPU, training, task generator, prompt
   builder, detector, or teacher-context implementation in M1.
5. Record new API dependencies, commands, failures, results and limitations;
   run M0 regression checks plus the full M1 suite, then stop.

Subprocess limits are resource containment for model-generated Python, not a
security boundary for hostile code. Linux/GPU acceptance requires the configured
server; local tests must not be skipped because this host is macOS.
