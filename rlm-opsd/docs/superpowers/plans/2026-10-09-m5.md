# M5 teacher gate plan

Scope: SPEC §5 only. The user explicitly authorizes implementation/tests of the
existing design; continue in the shared untracked workspace, as M0–M4 did.
No repeated design approval, commit, branch move, threshold invention, dataset
coverage bypass, M6 hook/training, or automatic manual rewrite without run evidence.

1. Write tests for explicit endpoint/gate config, threshold decisions and strict
   unknown handling. Implement eval/config.py and eval/decision.py. Criteria
   select teacher metrics by grouping, direction and user-supplied bound; each
   declares minimum known count and maximum unknown fraction. Missing groups or
   measurements cannot pass. Require a nonempty criterion list.
2. Write tests for preflight and paired rollouts using a local HTTP fixture plus
   actual Episode/REPL (not a fake detector). Implement eval/gate.py. Consume only
   load_tasks(..., split='dev_behavior') with normal decontamination validation;
   validate manifest hash, expected eligible family/bucket grid, detector family
   limits, prompt/model pins and endpoint declarations. Never send answers.
3. Run before/student and teacher/teacher variants over identical task order,
   sampling settings and model revision; keep separate frozen/root clients.
   Preserve original completion IDs and reasoning, geometry/buckets and trace
   provenance. Endpoint failures preserve partial logs and cannot pass the gate.
   Write behavior.md/csv, records.jsonl, run.json and gate.json/gate.md with links.
4. Test CLI and make teacher-gate. Default gate.yaml has required unset endpoint
   and acceptance values; detector thresholds remain unset. Add a no-network
   --check preflight and nonzero exit status for not-run/error/inconclusive/failed.
5. Execute authorized real run if its prerequisites become available; otherwise
   execute/record preflight and label real gate as not run, never substitute HTTP
   fixtures for model evidence. Full regression, exact source/API catalog,
   separate review, progress/docs and final artifact audit. Stop at M5 code;
   report any unmet M5 real-run acceptance criterion explicitly.

Known starting state: Apple Silicon host, no matching endpoint/credential env
names and common localhost inference ports closed; user previously deferred GPU
runs. User was asked asynchronously whether an endpoint is now available.
Existing data pool has coverage_complete=false. Gate and detector acceptance
settings must be chosen by the user under AGENTS hard rule 10.

Interfaces: GateConfig.from_yaml resolves file paths relative to gate config;
prepare_gate(config) returns sanitized dev inputs plus validated configs, prompt
builder and manifest provenance. run_gate(config, output_dir) performs sequential
paired endpoint rollouts and writes artifacts. evaluate_gate(metric_rows,
criteria) returns passed/failed/inconclusive plus every criterion's evidence.
CLI receives --config, --output, optional --check. Tests use clearly labelled
fixture pools/endpoints and test-only thresholds, not operational defaults.

User steering during M5: make OPSD primary, with an aligned frozen-base
teacher forward inside the trainer and no scoring server/API. Verify the pinned custom MultiLoRA mechanism and update SPEC §6 and
VERIFIED_APIS only; trainer integration remains outside M5. Source inspection
found in-place zero scaling, not a built-in disable_adapter context, and the
documentation records finite-residual, state-restoration and GPU-test limits.

Final regression exposed an existing sandbox cleanup race. Instrumented real
CPU-limit runs and deterministic red tests demonstrated repeated process-group
signaling and EOF before child reaping. Fix those shared harness paths without
weakening existing assertions, then rerun the harness/M5 and full suites.
