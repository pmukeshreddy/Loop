# M3 prompt implementation plan

**Goal:** Implement SPEC §3 only: x/y* builders, pinned Qwen3.5-27B chat
prefixes, token-ID suffix alignment, manual versioning, and harness use.

**Spec:** `docs/SPEC.md` §3; source prompts are authoritative. The user approved
M3 implementation and selected `Qwen/Qwen3.5-27B`. Existing task authorization
covers execution in the shared workspace, as in M0–M2; no commit or branch work.

**Architecture:** Named-placeholder rendering consumes only query/context
metadata and harness limits. A checksum-verified manual registry identifies the
privileged addition. A single pinned tokenizer/template and thinking setting
render both initial prefixes; alignment copies the supplied rollout suffix IDs.
The harness uses these messages and records the real manual version.

**Constraints:** No answers in the privileged addition, no full-context prompt
dump, no `str.format`, no decoding/re-tokenizing suffixes, no model weights or
GPU run, no M4 detectors/M5 gate/M6 teacher-request hook. Thinking defaults on
for both prefixes and is explicitly configurable. The user can change this
operational setting; no new evaluation threshold is chosen.

## Review focus

- Literal JSON, regex quantifiers, f-string braces, and placeholder-like context
  text must survive a single named substitution pass.
- Teacher/student user messages must stay identical, with only system content
  differing; answers or arbitrary task info must not enter template values.
- Prefix validation must reject an unrelated/truncated student prompt, and
  preserve even noncanonical token sequences verbatim across multiple turns.
- Manual/template tampering must fail checksum checks, and logged manual IDs
  must describe the actual rendered source, including recursive episodes.
- Thinking flags and template selection must not diverge between prefixes;
  tests cover both thinking modes and the real pinned tokenizer in a smoke run.

## Tasks

1. Write failing `tests/test_prompts.py` for literal-brace preservation, exact
   x/y* relationship, metadata/privacy, manual checksums and source selection.
   Implement `rlm_opsd/prompts/templates.py`, public exports, manual registry,
   immutable `manual_v1` snapshot and changelog. Keep canonical source bytes.
2. Write failing tests for pinned chat rendering and token-ID alignment, using
   a small real BPE tokenizer offline. Implement `chat.py`, pinned config/template,
   prepare/check CLI, and `build_teacher_sequence(student_ids, *, student_prefix,
   teacher_prefix)`. Download tokenizer artifacts only; verify against hashes.
3. Write failing harness integration/config tests. Make default Episode/Env use
   builders, query-only user messages, valid chunk-size fractions and recorded
   `manual_v1`. Preserve explicit custom-prompt support with accurate provenance.
4. Run targeted tests, real Qwen tokenizer smoke, and the full suite. Inspect
   pinned APIs, document exact commands/results and boundaries in PROGRESS and
   VERIFIED_APIS, review artifacts, and stop at M3.

Baseline: full suite passed (3 M0 + 92 pytest checks); the command wrapper then
failed on zsh's read-only `status` variable. The test log is preserved, and later
wrappers use `task_exit_code`. No test failure was suppressed.
