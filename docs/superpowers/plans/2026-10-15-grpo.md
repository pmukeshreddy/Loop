# Prime-RL repository GRPO implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan inline.

**Goal:** Continue from an OPSD checkpoint with grouped repository-solving rollouts and binary executable rewards.

**Architecture:** Extend the pinned official RLM training environment, keeping verifiers' rollout loop and Prime-RL's scheduler, token transport, optimizer, checkpoints, and inference weight updates. Root and children use the same policy and independent persistent Python namespaces in one Docker checkout per rollout. A separate pristine container receives only the submitted patch and the task's verifier.

GRPO is a separate top-level `rlm-grpo/` project with the `rlm_grpo` Python
package. It consumes an exported OPSD checkpoint, not the OPSD Python package.
It owns its dependencies, prompt assets, source overlay, configuration, CLI,
Make targets, and documentation. The reserved evaluation snapshot is an explicit
input shared across phases.

**Tech stack:** Existing pinned RLM, verifiers, Prime-RL, PyTorch, Docker CLI.

**Spec:** User's October 15 request and `04-grpo.md`; the user's +1/-1 reward and instruction to write code without tests supersede the earlier 1/0 reward and testing workflow.

## Constraints and decisions

- No tests or training runs in this implementation session. Read source and review code; report execution as not run.
- Workspace is an extracted source tree without `.git`; edit it directly, without commits/worktrees.
- Require a local merged OPSD checkpoint. Do not silently fall back to the original base model.
- Train root and child assistant tokens; mask all environment observations. Require recorded tokens/logprobs.
- Use leave-one-out advantages, asymmetric PPO clipping, no reward standard-deviation division, no KL or entropy bonus, and constant maximum-context normalization.
- Keep timed-out, truncated, unsubmitted, and infrastructure-failed rollouts out of the gradient and advantage baseline.
- Only explicit train/dev manifests may tune the policy. Reject public DeepSWE task/repository/query overlap.

## Review focus

- A child must actually execute Python in the task container and return original model tokens.
- Submission on the last allowed turn must execute before the stopping condition.
- Missing/malformed grader output must not masquerade as an incorrect model patch.
- Concurrent siblings and rollout cleanup must not leak containers or host credentials.
- Native trainer normalization and interleaving must preserve masking and the intended objective.
